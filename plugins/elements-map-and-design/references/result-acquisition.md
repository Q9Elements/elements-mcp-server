# Acquiring Elements results

Model Context Protocol (MCP) replies contain JavaScript Object Notation (JSON) data between `[TOOL DATA START]` and `[TOOL DATA END]`. Save that parsed data. Keep the selected server, space `teamId` and reference model `refModelId` through every call and drawing hand-off.

## Generic reads

Send `delivery: "file"` on eligible full reads. Accept small intact inline replies. Download whole-result/page files, keeping outer paging context, and restore nested `{file:{...}}` values at their original paths. Hydration clears the outer `_truncated.inFile` transport marker and retains the downloaded page's continuation markers. `scripts/acquire_result.py generic --input REPLY.json --out COMPLETE.json` performs that hydration. Use `--append` for each continuation page: it merges nested lists, joins component items by `nodeId`, and uses each current page's cursors. Any nested continuation keeps acquisition incomplete; `--node-ids ID,ID` verifies component coverage. Inspect item errors as gaps. A refusal (`_oversize.refusedInline`) is an acquisition failure; an intact informational `_oversize` marker is usable.

Follow `hasMore`, `nextSkip` or `_truncated.nextSkip`; ordinary list offsets advance by returned row counts. Component summary inbound paging follows its cursor even after empty or short pages. `get_metadata_component.page` applies to one component's summary, not full component batches. Full component reads use batches of at most 50, `detail: "full"` and `delivery: "file"`; join trimmed batch pages by node ID. History and usage batches hold at most 50 IDs, explanations at most 25. Verify every requested ID and preserve per-item errors. Hydrate and collect every authorized-space, reference-model, map, outline, package and health-detail page before making choices or deriving a model. Space-management calls take their own arguments, without generic delivery.

Poll only operations with polling states. Native jobs and explanations use `retryAfterSeconds`; outer throttling uses `retryAfter`. Running polls the same operation; failed ends the attempt. An explanation failed with `rate_limited` receives one retry after its supplied delay (60 seconds in this contract); another failure is a gap. Successful reads and writes without status are complete for that operation. Template-copy reads and writes can return running; wait on the same map's outline before proceeding. `get_process_map` complete with `empty:true` ends polling and uses the documented local-writer fallback.

## Native row jobs

`get_dependencies`, `list_metadata_by_criteria`, `get_metadata_source`, `get_access` and `run_code_search` return newline-delimited JSON (NDJSON) part files in row mode. A manifest contains counts, not rows. Keep arguments identical while polling running; follow `nextPartsFrom` using `partsFrom`. Download each index once, in index order, under one `resultId`. Failed is terminal for the attempt. Running totals describe work so far. Completion requires status complete, every part, final row totals, completed batches and all failures. Acquire `failedFile` whenever `failedTotal` exceeds inline `failed`; preserve each failure as an evidence gap, even when that node already produced rows. A new resultId starts a separate attempt.

Use `scripts/acquire_result.py native --input REPLY.json --out ROWS.ndjson` for each reply. It retains status, result identity, part descriptors and rows, counts and failure records in `ROWS.ndjson.acquisition.json`; exit 1 prints the continuation until coverage is complete. Use this sidecar for saved relationship, status and source rows. For playbook pull registers, retain these same fields plus `tool`, `nodeIds` and verified part descriptors. `skills/compare-design-to-implementation/scripts/save_pull.py ENG PULL TOOL --reply REPLY.json` acquires and updates that register. Other playbooks record the same complete envelope alongside their named parts. Empty success requires terminal completion and settled failure coverage. Source-row status/reason remains separate from job failures. Access rows are `{node,holder,access}` in default holder mode.

Dependency row calls send neither `limit` nor `skip`. Their canonical rows contain `node`, `related`, `relationshipDescription`, read/write and trigger flags; classify by `related.type`. Missing entry conditions require component or source evidence, or an explicit gap.

## Link lifetimes

Follow each descriptor's `expiresInSeconds` and verify bytes and Secure Hash Algorithm with 256-bit output (SHA-256) digest when supplied. Dependency, criteria, metadata-source and access parts last 1800 seconds in this contract. Generic result files and code-search parts last 120 seconds. Export archive links last 3600 seconds. Repeat identical requests for fresh links; native dependencies retain their native file delivery. Link validity, storage retention and completed-result reuse are separate contracts.

## Writes and names

Every final `create_map.name` is trimmed and must contain 2-80 characters, after overrides and transformations. Every write sends at most 100 changes and at most 10 new library names. A level supports at most 150 activities and 300 lines. Split a larger scope before emitting calls. Already-authorized removals carry `confirm:true` whenever required by more than five removals or more than 30 percent of level elements; resources and attributes count.

For compare write plans with `batches`, run `scripts/manage_batches.py next PLAN.json --result FINAL.saved.json` until done. Send only the printed arguments, preview each batch, save genuine responses and repeat. Receipts are stored under `.batches/<plan-stem>/<plan-hash>/`, bound to the complete plan including its changes and base version. A replacement plan starts with its own receipts. Earlier batch idMap and version resolve later references; final batchResults retain the genuine evidence. Status writes use this same batching seam automatically.

Advance on `saved:true` or a verified unchanged no-op. Running copy, blocking validation, partial_save, save_failed and timeout are separate outcomes. Read the level and outline and reconcile resources, attachments and children before retrying an uncertain save. Recover genuine responses when available; unresolved ref/key associations stop automatic replay. A diagram read does not reconstruct the original batch idMap. `being_edited` is a dry-run warning; `lock_held` refuses the real write.
