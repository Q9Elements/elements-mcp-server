# The engagement directory

Every file a run writes, who writes it and who reads it. `$ENG` is the engagement directory, the folder holding `execution-state.json`. Formats with a schema are checked by the script named; the agents' files follow the schemas in `../schemas/`.

| Path in `$ENG` | Written by (card) | Read by | Format |
|---|---|---|---|
| `execution-state.json` | the orchestrator, every card | every card, `build_solution_overview.py`, `solution-overview-writer` | `../templates/execution-state.json` |
| `levels/outline.json` | `get_process_map_outline` answer, saved whole (02) | `read_process_map.py`, `check_process_map.py check`, `process-quality-assessor` | Elements answer |
| `levels/<levelNumber>.json` | `get_diagram` answer with `include: ["all", "layout"]` and `delivery: "file"` with selected teamId, saved whole, one per level (02) | `read_process_map.py`, `check_process_map.py check`, `process-quality-assessor`, `render_diagram.py` (each process area's level) | Elements answer |
| `process-model.json` | `read_process_map.py build` (02) | `design.py`, `data-model-deriver`, `integration-deriver` | the process as read, in the shared model; never changed after card 02 |
| `model.json` | `read_process_map.py build` (02), then `design.py merge` (05, 07), rebuilt from `process-model.json` each time | `design.py`, card 06 (that it has entities), `access-deriver`, `solution-overview-writer`, `check_access_matrix.py`, `render_diagram.py`, `build_solution_overview.py` | the plugin's shared model (`schemas/ba-model.schema.json` at the plugin root) |
| `inventory.json` | `read_process_map.py build` (02) | `process-quality-assessor`, `data-model-deriver`, `integration-deriver`, `access-deriver`, `render_diagram.py` and `build_solution_overview.py` (each area's level and its link) | per level: activities with their verb, resources by type, line labels, metadata attachments retaining `refModelId`; across the map: every resource by type with the steps that use it |
| `check/mechanical.json` | `check_process_map.py check` (02) | `check_process_map.py score` | failing elements per level for the script rules |
| `check/wording.json` | `process-quality-assessor` (02) | `check_process_map.py score` | `../schemas/wording.schema.json` |
| `check/scores.json` | `check_process_map.py score` (02; `--check` writes nothing) | cards 03 and 07, `build_solution_overview.py`, `solution-overview-writer` | each level's score, pass or fail, and its findings |
| `evidence/pulls.json` | the orchestrator (04, 06): one entry per list tool call, with its parts' `index`, `rows` and `sha256` copied from the answer (and, for `get_access`, the `nodeIds` asked for) | `prepare_evidence.py`, card 06 (whether a kept access pull's `nodeIds` changed), `access-deriver` (which part files to read) | `{"<pull>": {"tool", "totalRows", "partsTotal", "parts": [{"index", "rows", "sha256"}]}}` |
| `evidence/<pull>-<index>.ndjson` | `curl` of each part (04, 06) | `prepare_evidence.py`, `access-deriver` (the `access-<n>` and `permission-holders` pulls), each reading only the parts `pulls.json` records | Elements rows |
| `evidence/packages.json` | the orchestrator (04): the `packages` of every `list_managed_packages` page, joined | `prepare_evidence.py` | `{"packages": [...]}` |
| `evidence/doc-inventory.json` | `system-doc-reader`, index mode (04) | `prepare_evidence.py` | `skills/map-process-from-data-model/schemas/inventory.schema.json` at the plugin root |
| `evidence/targets.json` | `prepare_evidence.py` (04) | card 05 (that it exists), `data-model-deriver`, `integration-deriver`, `build_solution_overview.py`, `solution-overview-writer` | the target system's objects (with their fields on the org route) and integration evidence, with gaps |
| `derive/data-model.json` | `data-model-deriver` (05), the solution architect's data corrections (07) | `design.py check-section`, `merge` and `slice`, card 06 (the entities' `nodeId`), card 07, `access-deriver`, `build_solution_overview.py`, `solution-overview-writer` | `../schemas/data-model-section.schema.json` |
| `derive/integrations.json` | `integration-deriver` (05), the solution architect's system corrections (07) | `design.py check-section`, `merge` and `slice`, card 07, `access-deriver`, `render_diagram.py` and `build_solution_overview.py` (which integrations serve each area), `solution-overview-writer` | `../schemas/integrations-section.schema.json` |
| `derive/access.json` | `access-deriver` (06; again after corrections) | `check_access_matrix.py`, card 07, `build_solution_overview.py`, `solution-overview-writer` | `../schemas/access.schema.json` |
| `derive/corrections.json` | the orchestrator (07) | card 06 (the access corrections of every round go to the `access-deriver` as `findings`), card 07 (a last round without `applied: true` is applied again), `design.py stale` | the solution architect's corrections, as given: `{"rounds": [{"date", "by", "corrections", "applied"}]}`; `applied` is set once the round is merged |
| `access-matrix.csv` | `check_access_matrix.py` (06; `--check` writes nothing) | card 07 (that it exists), `design.py stale` (its age), card 09 (its path), `build_solution_overview.py` (that it exists; the document names it and sums up `derive/access.json`) | one row per access row, in the solution architect's words; a deliverable in its own right, never listed in the document |
| `drawing/models/<name>.json` | `design.py slice` (08) | `draw-data-model`, `draw-system-architecture`, card 08 (every model drawn) | the shared model, one file per diagram |
| `drawing/<name>/` | the drawing skills' work folders (08) | `render_diagram.py` (its `preview.svg`), card 08 (`plan.json` and `review.json` for the resume rule, `review/top.json` for the links), card 09 (`review.json` for the final report) | the drawing protocol's files |
| `overview/areas/<step id>/` | `render_diagram.py` (09) | `render_diagram.py` | each process area's picture sources: `process.svg`, `data-model.json` and `architecture.json` with their offline layout plans |
| `overview/images/` | `render_diagram.py` (09) | `build_solution_overview.py`, card 09 (which pictures are missing) | one PNG per drawn diagram (`<name>.png`) and per process area (`area-<step id>-process.png`, `-data-model.png`, `-architecture.png`) |
| `overview/prose.json` | `solution-overview-writer` (09) | `build_solution_overview.py` | `../schemas/prose.schema.json` |
| `overview/<project>-solution-overview.docx` | `build_solution_overview.py` (09) | the solution architect | the deliverable |

Pull names used in `evidence/`: `objects` (Standard, Custom and External Object rows) and `fields` (card 04), one `integration-<slug>` per metadata type of `../data/integration-evidence-types.csv` (card 04; `{"notSynced": true}` for a type the org does not sync), and `access-1`, `access-2`, ... and `permission-holders` (card 06).

Every native pull retains terminal status, resultId, final counts, completed parts, failedTotal and all failed records (including failedFile coverage). Part hashes and row counts prove the files; terminal state and failures prove the coverage. Keep each result attempt separate and report source-row availability reasons as source gaps. See the shared result-acquisition contract.
