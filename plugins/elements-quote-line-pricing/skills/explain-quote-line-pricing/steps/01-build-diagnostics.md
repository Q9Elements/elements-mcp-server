# 01 Build diagnostics

State: `kickoff`

## Purpose

Gather the evidence needed to explain one quote line's price.

## Procedure

- [ ] Explain prerequisites and fill kickoff inputs.
- [ ] Prepare the evidence directory.
- [ ] Gather Salesforce and Elements evidence, then compute the diagnostic.
- [ ] Report the status and follow the matching outcome.

1. If `engagement.started` is null, set it to the current Coordinated Universal Time (UTC) and retain `engagement.playbook_version`. If `slots.route` is null, explain the prerequisites: Salesforce CPQ and Quote Line Microscope (QLM) are installed and the user has clicked its "Create Diagram" on the line; the user has the "Salesforce CPQ Admin" and "Elements Quote Line Microscope Admin" permission sets, plus the optional reads in `data/required-access.csv`; one data route is set up; the core Elements Model Context Protocol (MCP) connection is active in a space linked to this Salesforce org with its reference model synced. Price rule history also needs the Revenue Cloud flag and the CPQ price rule, condition and action objects selected for sync in Elements. History is optional. Explain that this covers one quote line's calculation and use `SCOPE-CALC-RULES` from `data/canned-messages.csv` for the calculator price rule boundary.
2. Fill `slots.route` (`cli` or `hosted-mcp`), `slots.org_alias` for the command-line interface (CLI) route, `slots.quote_line_ref` (Id or Name), and `slots.question` from the user's message, retaining stored values for inputs the message omits. A line reference in the message replaces `slots.quote_line_ref`; when it changes, clear `slots.quote_line_id` and all `diagnostics` fields, keeping the evidence directory on disk. Record the user's choices in `decisions_log`. If an applicable input is missing, take TR-01 before gathering.
3. Reuse `diagnostics.directory` and its saved responses only when its `q/plan.json` `line` equals `slots.quote_line_ref`; otherwise clear all `diagnostics` fields, keeping the evidence directory on disk. When `diagnostics.directory` is null, create `evidence/<line ref>-<UTC stamp>/` in the engagement directory and write its path to `diagnostics.directory`. The engagement directory and every `--dir` passed to a script are absolute paths. Run scripts from the plugin root and pass the absolute path of `diagnostics.directory` as `<dir>`.
4. Use the Salesforce Hosted MCP server connected to the org the user named and the connected Elements server whose tools include `get_space_context`; a server offering only `authenticate` is not connected. When more than one Salesforce read server is connected and the org is not clear, include the server choice in the existing step-2 kickoff ask. For `cli`, run `scripts/quote_line_diagnostics.py gather --target-org <alias> --line <ref> --dir <dir>`. For `hosted-mcp`, resolve the Salesforce Hosted MCP tool whose name ends in `soqlQuery`; if it does not resolve or is not authorized, treat the status as `route_error` and skip to the outcomes. Otherwise run `scripts/quote_line_diagnostics.py next --line <ref> --dir <dir>`. For each returned `{id, attempt, soql}`, call `soqlQuery` with `{"q": "<soql>"}` using that exact query. Pipe the unchanged response, or the file saved by the host, into `scripts/quote_line_diagnostics.py save --dir <dir> --id <Pnn> --attempt <n>`; use `--from <file>` for a saved file. Repeat `next` and save each response until only Elements calls remain. Do not author queries.
5. For either route, continue `next --line <ref> --dir <dir>` and call each printed Elements tool with its exact `args`; when a reply carries `file.url`, download it with `curl -sS -o <dir>/<Enn>.<b>.json "<file.url>"` and run `scripts/quote_line_diagnostics.py save --dir <dir> --id <Enn> --batch <b> --from <dir>/<Enn>.<b>.json`, otherwise save the inline reply unchanged by pipe or `--from <file>` with the same command, never retyping a response. Keep the active space unchanged (do not call `set_active_space`), continue until no calls remain, then run `scripts/quote_line_diagnostics.py compute --dir <dir>`; a missing model or node, failed Elements call, or incomplete Elements history is reported as `HISTORY_UNAVAILABLE` and does not block the build.
6. Read `status.json`: `status`, `warnings`, `quote_line_id`, `log_modified_at`, and `stale`. Write `slots.quote_line_id` from the result, using null when unavailable, and `diagnostics.file` (the absolute path to `diagnostic.json`) in `diagnostics.directory`. Report `diagnostic.json` `meta.quoteLineName` and the log time when available, `STALE-LOG` from `data/canned-messages.csv` when stale, and `HISTORY-UNAVAILABLE` from `data/canned-messages.csv` when `warnings[].code` includes `HISTORY_UNAVAILABLE`.

## Outcomes, in precedence order

The first that holds wins. For blocks, set `blocked.reason`, `blocked.owner` from `data/blocked-reasons.csv`, and `blocked.evidence` from the result, then continue to the recovery card.

- **TR-01: An applicable slot is missing, the Salesforce read server choice is unclear as described in step 4, or status is `line_not_found`.** For `line_not_found`, clear `slots.quote_line_ref`, `diagnostics.directory` and `diagnostics.file`, keep the evidence directory on disk, and use `LINE-NOT-FOUND` from `data/canned-messages.csv`. **Human moment, user:** ask for all missing inputs together. When asking for the route, recommend `cli` whenever the user can install and authenticate the Salesforce CLI; use `hosted-mcp` for users who cannot. Explain that on the hosted route the assistant copies query results to the script, and a copying slip can drop or change a value that the script cannot always detect. For a whole-quote question, include `QUOTE-NOT-LINE` from `data/canned-messages.csv` in that ask. Write `{"current_state": "kickoff", "current_step": "steps/01-build-diagnostics.md"}`. Next card: `steps/01-build-diagnostics.md`; stop for the answer.
- **TR-02: Status is `route_error`.** Set `blocked.reason` to `ROUTE_UNAVAILABLE`. Write `{"current_state": "blocked", "current_step": "steps/03-blocked-recovery.md"}`. Next card: `steps/03-blocked-recovery.md`.
- **TR-03: Status is `package_missing`.** Set `blocked.reason` to `PACKAGE_MISSING`. Write `{"current_state": "blocked", "current_step": "steps/03-blocked-recovery.md"}`. Next card: `steps/03-blocked-recovery.md`.
- **TR-04: Status is `access_gap`.** Set `blocked.reason` to `ACCESS_GAP`. Read `diagnostic.json` in `diagnostics.directory`; copy the `object` and `field` values from its `accessGaps[]` entries with `required: true` into `blocked.evidence`. Write `{"current_state": "blocked", "current_step": "steps/03-blocked-recovery.md"}`. Next card: `steps/03-blocked-recovery.md`.
- **TR-05: Status is `no_log`.** Set `blocked.reason` to `NO_QLM_LOG`. Write `{"current_state": "blocked", "current_step": "steps/03-blocked-recovery.md"}`. Next card: `steps/03-blocked-recovery.md`.
- **TR-06: Status is `built`.** Write `{"current_state": "diagnostics-built", "current_step": "steps/02-answer-questions.md"}`. Next card: `steps/02-answer-questions.md` in the same turn.
- **TR-07: Otherwise.** This outcome covers status `query_error` or `compute_error`, or any result matching no outcome above. Set `blocked.reason` to `QUERY_FAILED`. Write `{"current_state": "blocked", "current_step": "steps/03-blocked-recovery.md"}`. Next card: `steps/03-blocked-recovery.md`. For a result other than `query_error` or `compute_error`, record the default call and evidence in `decisions_log` and tell the user.

## Failure

If `python3` or the diagnostic script is missing, re-check their availability, record the missing prerequisite in `open_items`, and stay on `kickoff` until the prerequisite is available.
