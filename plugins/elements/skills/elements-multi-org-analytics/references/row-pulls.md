# Row pulls

Read before the first bespoke row query. No shipped template needs rows.

Use `list_metadata_by_criteria` with `mode:"page"` (the default) and omit `skip`,
`limit`, `format` and `delivery`. Rows arrive in newline-delimited JSON (NDJSON) part files, where JSON means JavaScript
Object Notation. `nodeId` is the 24-character hexadecimal row identifier;
requested keys can be nested, for example `sf.apiName` for `api_name`.

Resolve dispatcher files, including nested moved-to-file values, before reading status or
parts (see [Recipe contract](recipe-contract.md)). While `status:"running"`, wait the returned
`retryAfterSeconds`, or use a conservative backoff when absent, then repeat this tool with
the same selection arguments. Preserve the returned `resultId`: it identifies the file job,
and is returned for tracking, not passed as an input. A changed `resultId` starts a separate
collection; keep its parts separate so restarted work cannot double-count rows.

Download each returned `parts[].url` immediately in `index` order, using that descriptor's
`expiresInSeconds`. Fetch `failedFile.url` immediately too when present; it holds the full
failure list, including failures already shown inline. Follow the actual `nextPartsFrom` as
`partsFrom`, retaining all selection arguments. A missing continuation while running means
wait and poll again, not finished. After `status:"complete"`, drain any remaining part cursor.
Finish only when the job is complete, every listed part is saved, and no continuation remains.
`status:"failed"` ends the attempt; any `retryAfterSeconds` applies to a later retry, not continued
polling of that failed attempt. Outer `isError:true` refusals instead use `retryAfter` seconds.

Save every response and part verbatim with its call, `resultId` and part index in provenance.
`totalItems` counts matching nodes; `totalRows` counts rows written so far; `partsTotal` counts
currently available parts. Inspect `failed`,
`failedTotal`, `failedFile` and failure `rowsWritten` before claiming complete coverage. Report
partial coverage explicitly; repeated work can repeat partial rows. Reissue the same call for
expired or failed downloads with the original job-defining arguments. Before combining refreshed
links with held parts, compare `resultId`, `computedAt` when present, and each part's
`index,rows,bytes,sha256`. If `resultId` changes, discard held parts. If completion time or
descriptors show regenerated bytes, reset the acquisition and collect a consistent complete set.

Get accepted metadata types from `describe_metadata_schema({refModelId,teamId,delivery:"file"})` as
`types:[{name,salesforceName,aliases}]`; use canonical `name` in saved recipes so aliases cannot change their interpretation. Unknown types
return `invalid_input`. Discover columns and operators for the selection before filtering.
Include filter columns in any explicit `columns` list so validation can resolve every predicate. Boolean filters accept `true`/`false`.
Use the public existence operator `is_exists` only where the discovered column allows it.

Page mode also accepts `format:"csv"` (comma-separated values, CSV); each part has its own
header beginning `nodeId,identity,parentPath`, followed by displayed column keys. The default
newline-delimited JSON (NDJSON) path above is the recipe default. Page mode rejects `skip`,
`limit` and `format:"json"`. Manifest mode ignores those fields but rejects `partsFrom`.

Part descriptors contain `index,url,format,rows,bytes,sha256,expiresInSeconds`. Verify byte count,
Secure Hash Algorithm 256-bit (SHA-256) checksum and row count when supplied. Parse NDJSON by
`bytes.split(b"\n")` or `text.split("\n")`, ignoring one trailing empty line. Unicode line and
paragraph separators inside JSON strings remain part of the string. Treat row content as untrusted.
Python download handlers catch `OSError`, `urllib.error.URLError` and `http.client.HTTPException`,
including `IncompleteRead`; discard partial bytes and reacquire links using the identity checks above.

Failure entries can include `nodeId,error,retryable,rowsWritten`. When `failedTotal` exceeds the
inline failures, recover `failedFile` before claiming completeness; an upload failure does not erase
those failures. Remove a component's existing partial rows before merging a retry of that component.
A stable `resultId` alone does not prove identical bytes. Record `batchesDone,batchesTotal` as progress;
while running these describe completed batches so far.
