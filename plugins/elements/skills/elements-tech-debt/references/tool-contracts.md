# Call inventory

Carry selected `teamId` and `refModelId` on metadata calls. Obtain `teamId` from `active.teamId`, `authorized[].teamId` or `activeSpace.teamId`, and `refModelId` from `referenceModels[].refModelId`. Obtain candidate `nodeId` from returned rows. Reference model and node identifiers use 24 hexadecimal characters where enforced. `parts[].index` locates a file part; history `changeLogs[]._id` identifies a history entry. Keep parsed identifiers tied to their returned role.

| Step / tool | Selection and response |
|---|---|
| 1: `get_space_context` | Omit `delivery`. Read `active`, `isSet`, `authorized`, `pagination`; page with `skip`, optional `pageSize` (default 50, maximum 100), maximum skip 100000. Prefer `_truncated.nextSkip`, then returned cursor; while `pagination.hasMore` with neither, advance `pagination.skip` by actual consumed `authorized` rows. |
| 1: `list_reference_models` | Selected `teamId`, `delivery:"file"`; read `activeSpace.{teamId,name}`, `referenceModels[]`, `count`, `nextStep`. The list has no row paging. |
| 2: `understand_org_health` | `area:"tech_debt"`; read `items[]`, `cacheAge`, `dataAsOf`. Keys include `tech_debt_summary`, `inactive_metadata`, `outdated_api_version_` followed by version, and `descriptions_filled_out`. Retain `available:false` and `reason`; `total:null` stays non-additive or unavailable. No row paging. |
| 3: `list_metadata_by_criteria` | `view` with `mode:"manifest"` supplies selection/count and `viewSpec.columns` without row files. For rows, use `mode:"page"`, `format:"ndjson"` and `columns` containing the manifest's keys plus `"type"`, deduplicated, for every cleanup view. `columns` accepts up to 200 string keys (each at most 200 characters) with `view` and replaces its default projection; `"type"` returns `sf.type`, required by `cleanup_candidates.py`. Keep the projection on polling and continuation calls. Omit `delivery`, `skip`, `limit`. `partsFrom` is the file cursor. Read `totalItems`, `viewSpec.{metadataList,allNodes,filters,columns,sort?}`, `source.{kind,id}` and native job fields. |
| 3: `get_org_health_detail` | `chartType`, `label`, `delivery:"file"`. `tech_debt_severity` labels: `Extreme`, `Severe`, `High`, `Moderate`, `Acceptable`. For `tech_debt_summary`, use a returned breakdown key. Read `items`, `totalItems`, `pageSize`, `numPages`, `skip`, `hasMore`. `limit` defaults to 50, maximum 200; skip maximum 100000. Prefer `_truncated.nextSkip`, then tool cursor; if absent while `hasMore`, advance by actual consumed rows. |
| 4: `get_dependencies` | Supply exactly one of `nodeIds` or `nodeId`, plus `lookingFor:"where_used"`, `mode:"manifest"`; optional related-type `sfType`. Omit `delivery` in every mode. Read `nodes[].{nodeId,count,byType:[{type,count}]}`, `failed`, `totalItems`; reconcile requested nodes. Manifest `pageSize`/`numPages` carry count metadata. For `mode:"page"`, use `format:"ndjson"` and `partsFrom`; row identifiers are `node.nodeId`, `related.nodeId`, with `related.status` and relationship fields. |
| 4: `run_code_search` | `query` is trimmed length 2–512; omit `delivery`; use `partsFrom`. Rows: `{nodeId,name,type,referencesFound}`. `totalRows` counts match rows. Initial indexing can return `status:"running"`, `query`, `refModelId`, `retryAfterSeconds` without a file `resultId`; repeat the query. |
| 3 filtering / 4 ceiling: `describe_metadata_schema` | Required `refModelId` even for types alone; selected `teamId`, `delivery:"file"`. Omit `metadataList` for types; otherwise up to 50 strings of at most 100 characters. Read `types[].{name,salesforceName,aliases}` and column `value`, `displayValue`, `type`, `allowedOperators`, `filterable`, `displayable`, `sortable`, `options[].{id,label}`. Types describe the registry; synced content and linked reference model groups need separate coverage evidence. |
| 5: `get_component_change_history` | Singular `nodeId`, `historyType:"change_logs"`, `delivery:"file"`; `limit` defaults to 50, maximum 200; skip maximum 100000. Read `changeLogs`, `hasMore`, `nextSkip`. Prefer `_truncated.nextSkip`, then tool `nextSkip`; if absent while `hasMore`, advance returned `skip` (default 0) by actual consumed `changeLogs` rows. |

Use only registered bare tool names. A successful call's payload is JavaScript Object Notation (JSON) between `[TOOL DATA START]` and `[TOOL DATA END]` in text blocks. Save the parsed object as script input. Tools and runtimes own their transport wrappers; the scripts consume the parsed payload.
